# 第一轮低风险后端优化

日期：2026-10-19。基于 `5874f03` 的优化；发布时需同时验证代码、资源和 Cron，部署结果以实际发布记录为准。保留 Cloudflare + D1、既有 Node 替代运行时，以及原 TradingView 组件；不进行数据库迁移，不提高用户/品种/发送配额。

## 已实现

1. **唤醒可靠性**：写入只提交一次；仅对幂等 wake 做最多 3 次、单次 1.5 秒的有界重试。确认失败仍保留写入成功，API 返回 `effects.schedulerWake='pending'`，页面显示“修改已保存、后台待确认”，不自动重放写操作。
2. **独立恢复**：Worker 每分钟通过 Cron 调用 DO 内部 `/reconcile`。即使没有浏览器，仍可发现持久化工作并补设 alarm；空闲不轮询行情、不发送通知。恢复依赖平台执行和数据库可用，不承诺固定一分钟内恢复。
3. **认证限流**：用安装版本支持的 `/**` 兜底路径替换无效 `*`，只纠正默认小时请求窗口；保留小时记录清理周期、OTP 独立保护、Google 原生 3 次/10 秒规则。
4. **登录降级**：能力查询初始化失败返回 503 + `Retry-After`，进入现有可重试 UI，而不是伪造“管理员未配置登录”。
5. **策略一致性**：调度器默认租约统一取配置的 40 秒，不再声明 15 秒却执行 40 秒；不缩短覆盖网络/投递预算的安全余量。
6. **读取成本**：工作台使用 `/api/status?include=alerts` 合并状态与规则列表；共享一次认证/限流和规则读取。旧接口保留，旧服务没有内嵌数组时兼容回退。
7. **批量摘要**：列表通过一条 SQL 读取当前 pending 与最近完成事件，避免逐规则发出 SQL 请求；保留租户、代次、通知锁定、加密与配额契约。
8. **DO 探测合并**：合并同一 revision 的并发工作检查，正向检查最多复用 1 秒；不缓存空闲/失败结果，wake 和独立补偿强制重新核对。

9. **报价单跳**：Cloudflare 在一次协调器调用中完成元数据新鲜度、可用性检查与展示报价，不再先 `/market` 后 `/quote`；API 认证、严格参数校验与错误语义不变。
10. **小批次串行投递**：Cloudflare 默认每 tick 最多 4 次预留、每 drain 最多 4 次 claim/发送，非并行发送；评估 100 条、due 扫描 32 条、2.5 秒评估/25 秒 drain/9 秒发送/40 秒租约保护不变。结果不明立即停止本批，不重发该事件。

## 可验证的成本变化

| 场景 | 优化前 | 优化后 |
| --- | --- | --- |
| 正常每轮状态 + 警报 HTTP 请求 | 2 次 | 1 次，不含独立展示报价 |
| 20 条规则的完成历史摘要 SQL 调用 | 20 次 | 1 次，同时可带当前 pending |
| 同时到达的 20 个 DO 状态探测 | 独立发起工作检查 | 同 revision 合并为 1 次检查 |
| 每次 Cloudflare 展示报价的协调器往返 | 2 次 | 1 次 |
| 同时命中的规则、快速正常提供方 | 每轮最多 1 条 | 每轮最多 4 条，串行且受预算约束 |
| 首次 wake 丢失且无网页访问 | 等后续状态请求 | 独立 Cron 尝试修复 |

这些是请求/SQL 数量和故障行为验证，**不是 500 人吞吐压测结果，也不代表延迟固定降低某个百分比**。合并状态不是跨 D1/DO 的强一致事务；CAS 仍是修改冲突的安全边界。本轮只调整有界投递批次，不增加通知并发；大规模规则评估、行情采集和分片扩容留在下一轮，不放开人数与配额阈值。

## 验证与上线边界

- 后端/前端类型检查、生产构建、Cloudflare dry-run。
- 全套后端测试包含真实本地 D1/workerd；新增认证路径、唤醒超时/失败、后台独立修复、SQL 批量摘要、租户隔离和探测合并测试。
- 构建后的实际 React → 编译后 Node → SQLite → 本地提供方传输路径验证；不会发送真实邮件或 Pushover。
- 桌面/手机 UI 测试覆盖新旧接口、待确认提示、恢复后不重复提交、冷却及入场动画；TradingView 在 UI-only 测试中用明确标注的测试 frame，真实组件源码保持不变。
- PostgreSQL 可选集成测试缺少 `@electric-sql/pglite`，不宣称已验证真实托管 PostgreSQL。

本轮本地结果：类型检查、生产构建与 Cloudflare dry-run 通过；后端 32/32 批次、469 项通过、1 项跳过；实际本地端到端 7/7 流程、58 项检查；UI-only 29/29 流程、381 项断言；入场动画 12/12 场景。SQL 执行计划回归要求两条摘要分支按事件 ID 索引查找，不以整份用户历史为外层扫描。

**上线须部署代码并启用 Cron。** 正常 Wrangler 部署读取 `wrangler.jsonc` 的 `triggers.crons`；自定义 API 上传脚本需要另外同步触发器。发布前重新验证凭据和当前线上版本，保留全部生产绑定与 Secrets，先上传版本、核对后再切流；单独同步 Cron 并重新读取确认。
