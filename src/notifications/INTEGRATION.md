# Notification and scheduler integration

Portable exports live in `src/notifications/index.ts` and `src/scheduler/index.ts`. No Node-only modules or environment reads occur in these modules.

- `encryptSecret(encryptionKey: string, userId: string, field: 'userKey'|'appToken'|'receipt', value: string): Promise<EncryptedSecret>`
- `decryptSecret(encryptionKey: string, userId: string, field: 'userKey'|'appToken'|'receipt', envelope: EncryptedSecret): Promise<string>`

Pass `config.encryptionKey` (the canonical 64-hex or padded-base64 string from loadConfig), NOT bytes. The helpers call `decodeEncryptionKey` internally. AAD binds `open-alert`, application version `0.1.0`, envelope version 1, user ID, and field. Errors contain safe codes only. Never return envelopes or decrypted values to clients.

- `validatePushoverChannel({userKey, appToken, device?}, {fetch?, timeoutMs?} = {}): Promise<{valid:boolean,code:string|null}>`. Resolving retained private/shared token belongs to API before validation. Invalid credential shapes throw `NotificationError`; transport failures throw a safe `NotificationError`; a confirmed provider rejection returns valid=false. Channel PUT must validate with this helper before encrypting/saving. Validation does not send a message or count delivery quota.
- `createNotifications(config, {fetch?, now?} = {})` is the API port: `encrypt`, `validate(userId, channel)`, `test(userId, channel)`, `health()`. Aliases `validateCredentials`/`sendTest` are exported on the service. API owns `tests.claim`/`tests.finish`; this provider performs no second claim. Save validates only. Tests always use priority 0.
- `createNotificationService({config, repositories, fetch?, now?})`. `test(userId)` awaits durable tests.claim, sends normal priority 0, then tests.finish. It returns `{outcome:'sent'|'failed'|'uncertain'|'daily_limit'|'channel_unconfigured'|'forbidden',at,code}`; only sent maps to API success. API validates `{confirm:true}` and rate limits/origin/session before calling. `deliver(event)` is for ALREADY CLAIMED outbox events only; scheduler owns claim/finish. `health()` returns ComponentHealth. `channelProfile(userId)` returns safe ChannelProfile.
- `createScheduler({config, db, repositories, fetch?, now?, ownerId?, notifications?})` returns the shared engine. `start()` runs target 5-second timer polling; `stop()` awaits in-flight tick/drain and releases lease. `tick()` is one coalesced poll/lease/cache cycle; `drain()` performs one coalesced bounded delivery batch. DO wrapper calls tick from alarm and drain via waitUntil; tick never waits for provider delivery. `invalidate()` / `invalidateRules()` refresh active rules on next tick. `getMarkets()` returns `{markets,updatedAt,stale}`. `getPrices()` returns original timestamps. `status()` / `getStatus()` returns `{health,prices,notifications,lastPollAt,coordinatorId,pollIntervalMs,running,leaseFence}`. `isInstrumentSupported(instrument)` requires fresh live catalog. Timer start is optional; Workers alarms may call tick/drain without start. Exactly one engine per coordinator instance.

`createCoordinator` aliases `createScheduler`; `RuntimeSchedulerService` is the inferred engine type. `cycle()`/`once()` await one tick then one drain, `snapshot()` supplies the API runtime port and `catalog.get()` supplies its catalog port.

Scheduler acquires/renews its repository lease; failed/expired ownership stops new reservations and sends. Reacquisition increments fence and recovers old sending events as uncertain. No exactly-once provider guarantee is made. Feed: fixed HTTPS OKX instruments/tickers endpoints; dynamic live USDT swap catalog; 2 MiB/10-second request bounds; 5-second target; exponential failure backoff capped at 60 seconds. TradingView symbol is empty outside the 12 recognized mappings (BTC/ETH/SOL/XRP/DOGE/ADA/AVAX/LINK/DOT/LTC/BCH/TON); chart availability never limits backend live instruments. Active rules cache refresh 30 seconds, catalog refresh 60 minutes. Outbox batches <=20; one serialized provider request at a time; user rotation and due keyset continuation. Default lease 40 seconds, delivery deadline 9 seconds, batch budget 25 seconds. Rule evaluation budget 2.5 seconds/1000 rules with in-memory continuation. A provider that ignores cancellation leaves its claim uncertain and blocks further dispatch until that operation settles; tick remains independent.

Implemented repository correction: confirmed rejection retries must be scheduled at >=60 seconds after attempt 1, >=120 seconds after attempt 2. Tests and normal delivery both count atomic per-user/global quotas. Missing/corrupt credentials finish failed while keeping alert latch. Ambiguous requests finish uncertain and are never retried. All provider errors/health codes are safe; no response bodies, secrets or receipt values in logs/API.
